# 油站设备巡检清单

- 行业：石油
- 技术栈：React、Vite、TypeScript、Zustand、Ant Design
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

数据保存在浏览器 localStorage 中，方便后续扩展为接口、权限、图表或地图能力。

## 班组签收与异常处理

- **班组身份**：页面顶部切换「白班 / 夜班」（选择存在 sessionStorage 中，开两个标签页可分别扮演两个班组，共用同一份清单）。
- **当天唯一签收、全程留痕**：每台设备当天只能被一个班组签收。签收时记录签收班组、精确到秒的时间，并追加到该设备的「签收 / 处理留痕」时间线（只追加、不覆盖），交班时可逐条核对谁处理过什么。签收按自然日生效，跨天自动释放。
- **并发签收不覆盖（乐观锁）**：签收时模拟约 600ms 提交耗时，提交瞬间重新读取最新清单做 check-and-set，并带有 `rev` 版本号；另一标签页通过 `storage` 事件实时同步。两个班组几乎同时签收时，后提交的一方会看到「该设备已于 xx 被某班签收，不能覆盖对方记录」，清单同时回显对方的签收信息。后续标记异常、异常处理同样基于最新数据校验：只有当天签收的班组能操作自己的记录，对方记录只读。
- **异常置顶与计数**：标记异常必须填写异常现象；异常设备红色高亮并自动置顶到清单最前，顶部出现异常横幅，「待处理异常」指标同步计数。
- **处理完才恢复**：异常设备只有通过「处理异常」（处理措施必填、留痕）才能恢复为正常，无法直接流转掉；恢复后自动退出置顶。

### 复现并发签收

1. `npm run dev` 后打开两个标签页；
2. 标签页 A 选「白班」，标签页 B 选「夜班」；
3. 在同一台设备上先后（间隔 0.5 秒内）点击签收，后点击的一方会收到冲突提示，且不会覆盖先签收一方的记录与流水。
